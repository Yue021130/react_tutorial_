## 一、通用表单处理器：`updateField(field, value)`

### 核心代码

```jsx
const [form, setForm] = useState({
  username: '',
  email: '',
  role: 'user',
  subscribe: false,
});

const updateField = (field, value) => {
  setForm(prev => ({ ...prev, [field]: value }));
};
```

### `[field]: value` 是什么意思？

这是 ES6 的**计算属性名（Computed Property Names）**。

普通写法，键名固定：

```js
const obj = { username: 'Alice' };
```

计算属性名写法，键名来自变量：

```js
const field = 'username';
const obj = { [field]: 'Alice' }; // { username: 'Alice' }
```

### 调用过程

```jsx
updateField('email', 'abc@example.com');
```

展开后等价于：

```jsx
setForm(prev => ({ ...prev, email: 'abc@example.com' }));
```

### 为什么要 `...prev`？

React 的 state 必须**不可变更新**：

```js
// ❌ 错误：直接修改原对象
form.email = 'abc@example.com';
setForm(form);

// ✅ 正确：创建新对象，保留旧字段
setForm(prev => ({ ...prev, email: 'abc@example.com' }));
```

`...prev` 把旧对象的所有字段复制到新对象里，然后 `[field]: value` 覆盖要修改的那个字段。

## 二、state 变了，组件会重新渲染

### 核心机制

```jsx
function MyComponent() {
  const [count, setCount] = useState(0);

  // 每次 count 变化，这一整段函数都会重新执行
  const double = count * 2;

  return <div>{double}</div>;
}
```

当 `setCount(1)` 被调用：

1. React 把 `count` 更新为 `1`
2. React **重新调用** `MyComponent()`
3. 函数内所有代码重新执行
4. `double` 被重新计算为 `2`
5. JSX 重新计算，DOM 按需更新

### 注意：重新执行 ≠ 重新初始化

虽然组件函数重新跑了，但 `useState` 返回的是 React 内部保存的**当前值**，不是初始值：

```jsx
function Counter() {
  const [count, setCount] = useState(0);

  // 第一次渲染 count = 0
  // 点击后第二次渲染 count = 1，不是 0

  return <button onClick={() => setCount(count + 1)}>{count}</button>;
}
```

React 靠 Hooks 的**调用顺序**来对应每个 state。

## 三、派生校验：为什么可以直接写 `const isValid = ...`

```jsx
const isValid =
  form.username.length >= 2 &&
  form.email.includes('@') &&
  /^(?:[1-9]\d*|)$/.test(form.age);
```

### 为什么可以每次渲染都算？

因为函数组件每次渲染都会重新执行，`isValid` 是渲染过程中一个普通的 JavaScript 表达式。

```
form 变化 → 组件重新渲染 → isValid 重新计算 → disabled={!isValid} 生效
```

### 三种写法的区别

| 写法 | 作用 | 这里是否需要 |
|------|------|------------|
| `const isValid = ...` | 每次渲染重新计算 | ✅ 简单校验用这个 |
| `useMemo(() => ..., [form])` | 依赖变化时才重新计算 | 可以，但没必要 |
| `useEffect(() => {...}, [form])` | 副作用，如调接口 | ❌ 校验不是副作用 |

简单校验直接写就行，计算成本很低。

## 四、闭包陷阱与函数式更新

### 问题代码

```jsx
const addThree = () => {
  setCount(count + 1);
  setCount(count + 1);
  setCount(count + 1);
};
```

假设当前 `count = 0`，三次都基于同一个旧快照，实际只 `+1`。

### 原因

React 的更新是异步批处理的。`count + 1` 在传入 `setCount` 时就已经求值为 `1`：

```
队列: [ set 1, set 1, set 1 ]
结果: count = 1
```

### 正确写法

```jsx
const addThree = () => {
  setCount(c => c + 1);
  setCount(c => c + 1);
  setCount(c => c + 1);
};
```

函数式更新把计算规则交给 React，每次基于最新 state 计算：

```
队列: [ f1, f2, f3 ]
f1(0) → 1
f2(1) → 2
f3(2) → 3
结果: count = 3
```

### 一句话总结

> 直接传值是"提前算好答案交上去"；函数式更新是"交一个公式上去，React 按最新数据现算"。

## 五、常见表单字段的受控写法

| 元素 | 绑定属性 | 取值方式 |
|------|---------|---------|
| `input type="text"` | `value` | `e.target.value` |
| `input type="email"` | `value` | `e.target.value` |
| `input type="number"` | `value` | `e.target.value` |
| `textarea` | `value` | `e.target.value` |
| `select` | `value` | `e.target.value` |
| `input type="radio"` | `checked` | `e.target.value` |
| `input type="checkbox"` | `checked` | `e.target.checked` |

### 多选复选框（数组字段）

```jsx
const [form, setForm] = useState({ tags: [] });

const toggleTag = (tag) => {
  setForm(prev => ({
    ...prev,
    tags: prev.tags.includes(tag)
      ? prev.tags.filter(t => t !== tag)
      : [...prev.tags, tag],
  }));
};
```

# REACT的闭包陷阱

**闭包陷阱** = 函数"记住"了创建时的旧值，而不是使用时的最新值。

因为 **闭包会"冻结"变量，而函数式更新会"实时读取"最新值**。



## 在 React 里为什么成了"陷阱"？

React 每次渲染，组件函数都会重新执行，产生一套**全新的 props 和 state**。但事件处理函数是在某一次渲染中创建的，它"记住"的是**那一次渲染的快照**。

```jsx
function Counter() {
  const [count, setCount] = useState(0);

  const handleClick = () => {
    setTimeout(() => {
      alert(count);  // ← 这里的 count 是"快照"，不是"实时值"
    }, 3000);
  };

  return (
    <div>
      <p>当前 count: {count}</p>
      <button onClick={handleClick}>
        点我，然后3秒内多点几次+
      </button>
      <button onClick={() => setCount(count + 1)}>+</button>
    </div>
  );
}
```

**操作流程：**

1. 页面显示 `count: 0`
2. 点击"点我"按钮 → `handleClick` 被创建，它闭包里的 `count` 是 `0`
3. 在 3 秒内，你点了 3 次 `+`，页面显示 `count: 3`
4. 3 秒后弹窗：`alert(0)` ← **陷阱！** 它弹的是旧值 `0`，不是最新的 `3`

`handleClick` 是在 `count=0` 那次渲染中创建的，它的闭包里永远锁死了 `count=0`。



## 更隐蔽的陷阱：异步请求

```jsx
function Search() {
  const [query, setQuery] = useState('react');

  useEffect(() => {
    fetch(`/api/search?q=${query}`).then(res => res.json()).then(data => {
      setResults(data);  // 如果 query 已经变了，这是旧请求的结果
    });
  }, [query]);
}
```

如果用户快速输入"react"→"react native"，第一个请求可能后返回，覆盖了第二个请求的结果。这也是闭包陷阱的一种表现。



## 如何避免？  |   ==传入函数进行更新==

### 方法 1：函数式更新（针对 state）

```jsx
// ❌ 闭包陷阱：count 是旧快照
setCount(count + 1);

// ✅ 安全：React 传入最新值
setCount(c => c + 1);
```

### 方法 2：useRef（获取实时值）

```jsx
const countRef = useRef(count);
countRef.current = count;  // 每次渲染更新 ref

setTimeout(() => {
  alert(countRef.current);  // 永远是最新值
}, 3000);
```

### 方法 3：依赖数组 + 重新创建函数

```jsx
useEffect(() => {
  const handler = () => {
    console.log(count);  // 每次 count 变，effect 重新执行，handler 重新创建
  };
  window.addEventListener('click', handler);
  return () => window.removeEventListener('click', handler);
}, [count]);  // ← 依赖 count，count 变了就重新订阅
```

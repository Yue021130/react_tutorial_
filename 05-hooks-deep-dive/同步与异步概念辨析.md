# React 中同步与异步概念辨析

> 从 `useLocalStorage` 里的 `localStorage.setItem()` 是否同步这个问题引申出来。

---

## 一、问题背景

在 `useLocalStorage` 自定义 Hook 中：

```jsx
useEffect(() => {
  localStorage.setItem(key, JSON.stringify(value));
}, [key, value]);
```

有同学问：

> “`useEffect` 不是异步的吗？`state` 更新也是异步的，这里写 `localStorage` 怎么是同步写入？”

其实这里有**几个概念要分开**，确实容易混。

---

## 二、`localStorage.setItem()` 是同步 API

```js
localStorage.setItem('key', 'value');
console.log('这行一定在写入完成后才执行');
```

浏览器提供的 `localStorage` 操作**就是同步的**。

调用完这行代码，数据已经写到浏览器本地存储了。它不是异步的，不需要 `await`。

---

## 三、`useEffect` 本身也不是异步的

`useEffect` 的回调函数是**普通函数**，里面的代码从上到下同步执行：

```jsx
useEffect(() => {
  console.log('1');
  localStorage.setItem(key, JSON.stringify(value));
  console.log('2');
}, [value]);

// 输出顺序一定是：1 → 写入完成 → 2
```

所以“同步写入 localStorage”指的是：**这行代码会立即、同步地把数据存到 localStorage**。

---

## 四、state 的“异步”到底是什么？

`setState` 的“异步”不是说 `setState` 这个函数调用本身是异步的，而是说：

```jsx
setCount(count + 1);
console.log(count); // 这里可能还是旧值
```

`setState` 调用后会**安排一次重新渲染**，但当前函数继续用旧值执行。新值要等下一次渲染才生效。

```jsx
setCount(c => c + 1);
console.log(count); // 旧值
// 过一会儿 React 重新渲染，count 才变成新值
```

所以 state 更新是**延迟生效**，不是 `localStorage.setItem` 这种立即生效。

更精确地说：

> `setState` 调用是同步的，但它引起的重新渲染和状态生效是异步/延迟的。

---

## 五、`useEffect` 的“异步时机”是什么意思？

有时候说 useEffect “异步”，是指它**在渲染完成后才执行**。

```jsx
function App() {
  const [count, setCount] = useState(0);

  useEffect(() => {
    console.log('effect 执行');
  });

  console.log('渲染中');

  return <button onClick={() => setCount(c => c + 1)}>{count}</button>;
}
```

点击按钮后执行顺序：

```text
1. 渲染中        ← 组件函数执行
2. effect 执行   ← 渲染完成后才执行 useEffect
```

所以 useEffect 是**在渲染完成后才执行**，从这个角度说它比渲染“晚一步”。

但 effect 内部的代码仍然是**同步执行**的。

---

## 六、概念对比表

| 操作 | 函数调用是否立即执行 | 结果是否立即生效 | 说明 |
|------|------------------|--------------|------|
| `localStorage.setItem()` | ✅ 同步 | ✅ 立即写入 | 浏览器同步 API |
| `setState()` / `setCount()` | ✅ 同步调用 | ❌ UI 稍后更新 | 安排重新渲染 |
| `useEffect(fn, [])` | ✅ effect 同步执行 | ✅ 渲染完成后立即执行 | 比渲染晚一步 |
| `fetch()` / `axios.get()` | ✅ 同步调用 | ❌ 数据异步返回 | 返回 Promise |

---

## 七、分析总结

1. **不要把“useEffect 在渲染后执行”理解成“useEffect 是异步函数”**

   `useEffect` 的回调是普通同步函数，只是执行时机在渲染提交之后。

2. **不要把“state 更新延迟生效”理解成“setState 调用是异步的”**

   `setState` 调用本身是同步的，但它不会立即改变当前作用域里的变量值，而是触发一次重新渲染，新值在下次渲染才可用。

3. **`localStorage.setItem()` 就是同步写入**

   在 `useEffect` 里调用 `localStorage.setItem()`，数据会立即持久化到浏览器。这是 localStorage API 的特性，和 React 的渲染机制无关。

4. **为什么 `useLocalStorage` 用 `useEffect` 写入？**

   因为写入 localStorage 是副作用（side effect），不属于渲染本身。React 要求在 `useEffect` 中处理副作用，而不是在渲染过程中直接做。

   ```jsx
   // ❌ 不要在渲染中直接操作 localStorage
   function Demo() {
     localStorage.setItem('key', value); // 每次渲染都写，浪费且不规范
     return <div>{value}</div>;
   }

   // ✅ 在 useEffect 中处理
   useEffect(() => {
     localStorage.setItem('key', value);
   }, [value]);
   ```

---

## 八、一句话总结

> `useEffect` 里的 `localStorage.setItem()` 是同步写入。所谓“同步”是指 localStorage 写入操作本身是立即完成的，不是异步 API；`useEffect` 只是比渲染晚一步执行，但执行时是同步的。
